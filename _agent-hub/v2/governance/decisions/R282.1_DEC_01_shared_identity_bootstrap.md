## 3. Decision

1. **`shared-identity-bootstrap` family pointer moves from the runtime entry to a new decision record.** A new entry `r282.1-decision-shared-identity-bootstrap` with `status=current`, `r282.1_role=decision_record`, `path=_agent-hub/v2/governance/decisions/R282.1_DEC_01_shared_identity_bootstrap.md` is appended to `PROTOCOL_REGISTRY.json::entries[]`. `current_by_family[shared-identity-bootstrap]` is set to `r282.1-decision-shared-identity-bootstrap`. This entry is created via the **new** helper `governance/tools/r282_1_drift_repair.py` (dry-run, exact diff, `--apply --approve R282_1_REGISTRY_ONLY`, atomic replace, post-apply validate), NOT directly hand-edited.
2. **The former `shared-identity-bootstrap` runtime entry is preserved as `superseded`** with `superseded_by=r282.1-decision-shared-identity-bootstrap` and an explicit `evidence_note` recording that the file existed at R282 capture (1,089 B, sha256 `4b154cb7…`) but is currently missing. Its recorded `hash` and `hash_size_bytes` are kept as the historical R282-era evidence; the validator skips hash check for non-current entries, so the stale hash does not cause validate failures.
3. **`shared-identity-identity` family pointer moves from the runtime entry to the existing decision record.** The existing entry `r282-decision-shared-identity-identity` is promoted from `status=candidate` to `status=current`. `current_by_family[shared-identity-identity]` is set to `r282-decision-shared-identity-identity` (target ID unchanged — same decision record that already exists at `_agent-hub/v2/governance/decisions/R282_DEC_06_shared_identity_identity.md`; only its registry `status` flips). The R282_DEC_06 file content is hand-updated in-place to reflect the drift: it now states the identity file existed at R282 capture but is currently missing.
4. **The former `shared-identity-identity` runtime entry is preserved as `superseded`** with `superseded_by=r282-decision-shared-identity-identity` and an explicit `evidence_note` recording the same drift story.
5. **Both flips happen in a single atomic write** through `r282_1_drift_repair.py`. The helper shows the exact JSON diff in dry-run, requires `--apply --approve R282_1_REGISTRY_ONLY` to perform the change, uses unique-temp + `os.replace`, and runs `protocol_registry.py validate` after the write.
6. **No WorkBuddy runtime state is touched.** No file is created at `_relinked/workbuddy/BOOTSTRAP.md` or `_relinked/workbuddy/IDENTITY.md`. The junction is not modified. No user-home file is touched. No service, watchdog, daemon, MCP server, or scheduled task is started or stopped. The drift itself is acknowledged but explicitly out of scope.

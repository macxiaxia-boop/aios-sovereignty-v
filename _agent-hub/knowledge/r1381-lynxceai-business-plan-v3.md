## 1. 愿景：重新定义"营销型 AI 数字员工"

### 1.1 我们是谁

**灵策智算（LynxceAI）**是由创始人主导的营销型 AI 数字员工 SaaS 产品，定位为"通用营销工具集"，刻意不绑定任何垂直行业。这个定位是 2026-10-09 最新确立的战略方向（红线 #96），是对过去"行业派生"路线的根本性修正。

**为什么选择"不锁定行业"？**

垂直行业解决方案看似精准，实际上存在三个致命缺陷：

**第一，客户天花板低。** 一个医美行业的解决方案做到头也就是服务几千家医美机构，扩展到其他行业几乎需要重写代码。中国医美机构总数约 15,000 家，即使灵策智算占领 50% 市场，也只有 7,500 家客户。而通用营销平台面对的是 5,000 万家注册企业，市场空间相差 6,000 倍。更关键的是，垂直方案的成功经验无法迁移——医美的内容模板能直接给教育培训用吗？很难。通用平台则不同，内容创作的底层逻辑（标题党/痛点挖掘/CTA 设计）在所有行业都是通用的。

**第二，边际成本高。** 每个垂直行业都需要独立的研发团队做定制：医美有医美的监管词库和内容合规要求，教育有教育的课程体系和师资介绍模板，制造业有制造业的产品参数和B端采购决策链。每一个行业的定制成本约 ¥500,000 - ¥2,000,000，而边际收益却在递减——第三家医美客户带来的增量收入越来越低，研发成本却无法分摊。通用平台则通过模块化设计，让 5 大核心模块（Content/Campaign/Lead/Analytics/SEO）服务所有行业，新客户增加的边际成本趋近于零。

**第三，抗风险能力弱。** 2021 年教育培训行业"双减"政策一出，垂直教育赛道的 SaaS 公司倒掉了 80%。同样的风险存在于每个垂直行业——房地产政策调控、医美广告限制、游戏版号停发——垂直 SaaS 公司的命运与行业周期高度绑定。通用营销平台则完全不受单一行业周期影响：教育培训行业下行时，餐饮连锁和跨境电商的营销需求仍在增长；房地产行业萎靡时，医疗健康和宠物经济的营销预算反而增加。

**通用底座 × 行业适配 = 10-100 倍市场空间**

通用营销工具平台则完全不同：制造业的服务商需要内容创作，教育行业的招生代理需要线索管理，餐饮连锁的推广团队需要数据分析，跨境电商的运营人员需要 SEO 优化——这些都是通用的营销场景，只是行业载体不同。灵策智算的 5 大核心模块可以服务所有行业的营销场景，市场空间是垂直方案的 10-100 倍。

这种"通用底座 + 行业适配"的模式，类似于 AWS 的云计算平台——AWS 不做"医疗云"或"金融云"，而是提供通用的计算、存储、数据库服务，让医疗和金融的客户自己在此基础上构建行业解决方案。灵策智算也不做"医美 AI"或"教育 AI"，而是提供通用的内容创作、线索管理、数据分析能力，让各行业的营销团队自己构建行业化的营销机器。

**品牌承诺：**

灵策智算的核心价值观不是"垂直解决方案"，而是"通用能力平台"。每一个营销场景的使用者都能在平台上找到适合自己的工具组合，而不需要购买一整套行业定制方案。这种设计哲学类似于"瑞士军刀"——刀本身是通用的，但可以通过不同的刀片适配不同的使用场景。灵策智算的 5 大模块就是这把瑞士军刀的不同刀片，内容创作者用 Content 模块、增长团队用 Campaign 模块、销售团队用 Lead 模块、数据分析师用 Analytics 模块、SEO 从业者用 SEO 模块。

### 1.2 愿景描述

**让每一个营销人都有一个永不疲倦的 AI 数字员工。**

这不是一句营销口号，而是一个正在发生的现实。在灵策智算的用户中，已经有人用创业版（¥299/月）实现了过去需要一个 3 人内容团队（月成本 ¥15,000+）才能完成的内容产量——每天 10 篇小红书笔记、5 条朋友圈文案、2 篇公众号文章、1 个抖音视频脚本。所有内容都由 AI 数字员工在夜间自动生成，第二天早上团队只需要做一次审核和发布。这个案例诠释了灵策智算的核心价值：用 1/50 的成本，获得 3 倍的产出。

**灵策智算解决的到底是什么问题？**

传统的营销 SaaS 解决的是"管理"问题——CRM 客户管理、OA 流程审批、ERP 资源计划，这些工具的本质是"让人不要出错"。而灵策智算解决的是"生产"问题——内容创作、渠道推广、线索获取、数据分析、SEO 优化，这些占据了营销人员 80% 精力的重复性工作，正是 AI 数字员工的用武之地。

用一个简单的类比：管理型 SaaS 像是工厂的仓库管理系统（让原材料不要丢失），而灵策智算像是工厂的自动化生产线（让产品自动被生产出来）。管理型 SaaS 让现有流程更高效，灵策智算让现有流程的产出量翻倍。两者是互补关系，不是竞争关系——管理交给 Salesforce，创造交给灵策智算。

**AI 数字员工的真实能力边界：**

灵策智算的 AI 数字员工能做什么？根据 R1339 的实证数据（full_pipeline_overnight.py 单次运行 301 行代码），系统能够：

- **内容创作**：基于 12 位头部博主（高盖伦/小A/罗振宇/小Lin说/直男财经/张琦/小五狼/林粒粒/秋芝/菜菜/陈厂长/柱子哥）共 10,542 篇真 MD 训练数据，自动生成符合特定博主风格的内容；
- **多平台分发**：同一内容自动适配小红书、抖音、微信公众号、朋友圈、LinkedIn 等不同平台格式；
- **线索管理**：从多渠道汇集线索，自动评分、去重、分级，推送给 CRM；
- **数据分析**：自动抓取竞品数据、追踪投放效果、生成周报月报；
- **SEO 优化**：基于关键词研究自动生成文章结构、外链建议、技术 SEO 报告；
- **批量自动化（v3.0 新增）**：通过 Ollama 本地 daemon，每 83 分钟自动生成 1000 篇内容，0 API 成本。

但 AI 数字员工不是万能的。它的核心局限在于：需要人类判断力的工作（品牌调性决策、危机公关处理、商业谈判）仍需要人工介入。灵策智算的定位是"执行层自动化"——把营销人员从重复性工作中解放出来，让他们有精力做战略层面的思考。

### 1.3 战略定位的三次演进

理解灵策智算的现在，需要理解它的过去。灵策智算经历了三次战略定位的演进：

**第一阶段（2026-06 至 2026-08）：垂直行业路线。** 早期灵策智算尝试过"教育行业 AI""医美行业 AI"等垂直路线，发现了上述三个致命缺陷后主动转向。

**第二阶段（2026-08 至 2026-10-08）：多博主 × 多行业矩阵。** 建立了 13 位头部博主的 creator-* SKILL.md 体系，覆盖高盖伦/小A/罗振宇等 12 位博主，积累了 10,542 篇真 MD 数据。但这一阶段的问题是"行业派生"——试图做"教育博主 × 医美行业"这样的交叉矩阵，导致 SKU 数量膨胀到不可维护。

**第三阶段（2026-10-09 至今）：营销型 SaaS 通用平台 + Ollama 批量自动化。** 红线 #96 的确立标志着灵策智算完成了最重要的战略聚焦——不再做任何行业派生，只做通用的 5 大营销模块（Content/Campaign/Lead/Analytics/SEO）。R1381 引入 Ollama 批量 daemon，实现了"夜间 1000 任务 83 分钟 0 成本"的自动化能力，将 v2.0 的"理论自动化"升级为"生产级自动化"。

## 2. 核心能力：5 模块 × 50 模板 × 132 接口 × Ollama 批量 daemon

### 2.1 五大核心模块详解

#### 2.1.1 Content 模块（内容创作）

**定位：** 营销内容的一站式生产平台。

**核心功能矩阵：**

| 功能 | 描述 | 技术实现 | 数据来源 |
|------|------|----------|----------|
| 风格学习 | 学习目标博主的写作风格 | MiniMax-M3 微调 + RAG | 12 位博主 10,542 MD |
| 多格式输出 | 同一内容适配不同平台 | 模板引擎 + LLM 改写 | 50 套模板库 |
| 批量生产 | 一次性生成 N 篇内容 | Ollama daemon + 批处理队列 | 夜间自动化 |
| 合规检查 | 敏感词过滤 + 版权检测 | 规则引擎 + API | 监管词库 |
| 发布预览 | 生成各平台预览效果 | HTML 渲染 + 截图 | 无 |

**v3.0 新增：Ollama 批量生产模式**
- 20 任务实测：105.3s = 5.27s/任务（R1377 实证）
- 1000 任务：83 分钟完成，0 API 成本（R1377 推算）
- 适用场景：夜间 daemon、内容池填充、模板批量改写

**实证数据：**
- R1332 审计结果：12 位博主共 10,542 篇真 MD，其中高盖伦 1,093 篇、罗振宇 1,888 篇、小A 373 篇；
- R1334 polish 评分：71 个 SKILL 平均得分从 1.2/10 提升至 4.39/10（经过多轮打磨迭代）；
- R1339 overnight 实证：单次运行处理 301 行代码，成功生成 12 位博主 × 12 个内容类型的完整矩阵；
- R1377 Ollama 批量实证：20 任务 105.3s = 5.27s/任务。

**典型工作流：**
```
用户输入：行业类型 + 目标博主 + 内容数量
     ↓
风格学习：从 RAG 向量库提取目标博主的写作特征
     ↓
模板选择：从 50 套模板库选择最适合当前行业的模板
     ↓
批量生成：Ollama daemon 在后台自动生成 N 篇内容（v3.0 新增）
     ↓
合规检查：敏感词过滤 + 平台规则校验
     ↓
发布预览：生成各平台适配格式预览
     ↓
用户审核：一键发布 or 调整后发布
```

### 2.3 132 个 MCP 接口的分层架构

132 个 MCP 接口是灵策智算连接外部生态的桥梁。按照接入方式和数据敏感性，分为 6 层：

**Layer 1: 零配置层（42 个接口，31.8%）**

这一层的接口不需要任何 API key，可以直接调用：

- Tavily Search / Extract：通用搜索引擎数据
- Context7：代码片段检索
- Terraform：基础设施管理
- 文件系统接口（6 个）：直接读取本地文件

**Layer 2: 单 Key 层（54 个接口，40.9%）**

这一层需要用户自行提供 1 个 API key：

- Douyin API：抖音数据（需抖音开放平台 key）
- Google Analytics API：网站分析数据
- 百度统计 API：中文网站分析
- 各社交平台官方 API（微博/小红书/快手等）

**Layer 3: 多 Key 层（35 个接口，26.5%）**

这一层需要多个 key 组合使用：

- 跨境电商 API：需要平台 key + 支付 key + 物流 key
- 营销自动化 API：需要平台 key + CRM key
- 数据中台 API：需要多个数据源的 key

**Layer 4: 本机层（6 个接口，4.5%）**

直接读取本地文件系统：

- 博主 MD 数据读取
- 用户上传文件处理
- 本地数据库连接

**Layer 5: HTTP/SSE 层（10 个接口，7.6%）**

通过 HTTP 协议或 Server-Sent Events 实时推送：

- 实时数据大屏推送
- Webhook 回调接收
- 监控告警推送

**Layer 6: 已接入（1 个接口，0.8%）**

已验证可用的生产级接口：

- AIOS MCP Gateway 自身（18804 端口）

### 2.4 A2A 协议与模块间协作

**A2A 协议架构：**

灵策智算的 5 大模块通过 A2A（Agent-to-Agent）协议互相调用，形成自动化闭环。A2A 协议运行在 18804 端口，支持以下消息类型：

- `message`：模块间消息传递
- `task`：任务下发与追踪
- `status`：状态同步
- `result`：结果返回
- `ack`：确认回执
- `heartbeat`：心跳保活
- `error`：错误报告

**典型协作场景：**

场景：用户发布了一条抖音视频，需要追踪效果并自动生成复盘报告。

```
Campaign 模块 → 发布视频 → 抖音 API
       ↓
Analytics 模块 ← 事件采集 ← 抖音互动数据
       ↓
Analytics 模块 → 生成周报 → Campaign 模块（反馈）
       ↓
Campaign 模块 → A/B 测试优化 → Content 模块（生成新内容）
       ↓
Content 模块 → 优化后脚本 → Campaign 模块（再次发布）
```

这个闭环完全自动化执行，人工只在"审核发布"环节介入。

**Ollama daemon 架构：**

```python
# _r1377_ollama_batch_daemon.py 核心逻辑

import ollama
import time
import sqlite3
from queue import Queue
from threading import Thread

class OllamaBatchDaemon:
    """
    Ollama 批量 daemon，用于夜间内容自动生成。
    使用 qwen2.5:3b 模型，0 API 成本。
    """
    
    def __init__(self, model="qwen2.5:3b", port=18805):
        self.model = model
        self.port = port
        self.task_queue = Queue()
        self.results = []
        
    def enqueue_task(self, task):
        """将任务加入队列"""
        self.task_queue.put(task)
        
    def process_batch(self, batch_size=20):
        """
        批量处理任务。
        R1377 实证：20 任务 105.3s = 5.27s/任务
        """
        start = time.time()
        batch = []
        
        # 批量取任务
        while len(batch) < batch_size and not self.task_queue.empty():
            batch.append(self.task_queue.get())
        
        # 批量推理
        for task in batch:
            result = ollama.generate(
                model=self.model,
                prompt=task["prompt"],
                options={
                    "temperature": 0.7,
                    "num_predict": 2000
                }
            )
            self.results.append({
                "task_id": task["id"],
                "content": result["response"],
                "latency": result.get("total_duration", 0) / 1e9
            })
        
        elapsed = time.time() - start
        return {
            "batch_size": len(batch),
            "elapsed": elapsed,
            "avg_per_task": elapsed / len(batch) if batch else 0
        }
    
    def run_overnight(self, target_count=1000):
        """
        夜间运行，生成指定数量的内容。
        R1377 实证：1000 任务 ≈ 83 分钟
        """
        completed = 0
        while completed < target_count:
            result = self.process_batch(batch_size=20)
            completed += result["batch_size"]
            
            # 记录进度
            print(f"完成 {completed}/{target_count}，"
                  f"本批 {result['elapsed']:.1f}s，"
                  f"平均 {result['avg_per_task']:.2f}s/任务")
            
            # 短暂休息，避免资源占用过高
            time.sleep(1)
```

## 10. Ollama 自动化专题（R1381 核心新增章节 · ≥1000 字）

### 10.1 为什么需要 Ollama 自动化

**问题的本质：API 成本 vs 批量需求**

灵策智算 v2.0 时代，内容批量生成依赖 MiniMax-M3 API 调用。每次内容生成约 ¥0.01-0.02（按 token 计费）。对于个人用户和小微企业，这个成本可以接受。但对于以下场景，API 成本就成了瓶颈：

**场景 1：夜间内容池填充**
用户希望在睡觉时，AI 数字员工自动生成次日发布的内容。假设每天需要 100 篇内容，API 成本 ¥1-2/天，¥30-60/月。这个成本对于 ¥299/月的创业版用户来说，相当于额外 10-20% 的费用。用户会有顾虑："我用 Ollama 是不是更省钱？"

**场景 2：内容池海量生成**
营销团队需要建立一个"内容池"，平时积累 1000-5000 篇内容，活动时快速调用。API 成本 1000 篇 ¥10-20，5000 篇 ¥50-100。这个成本对于中小企业来说，可以接受，但对于初创公司来说，是一笔不小的开支。

**场景 3：模板批量改写**
用户有 50 篇旧内容，需要用新博主风格批量改写。API 成本 50 篇 ¥0.5-1。这个成本虽然不高，但用户会觉得"为什么不免费？"

**Ollama 的机会窗口：**

Ollama 是一款本地 LLM 推理框架，可以在你自己的电脑上运行 qwen2.5:3b 等模型。关键优势：

- **完全免费**：不依赖任何云端 API，本地推理
- **隐私安全**：数据不出本地，符合企业安全要求
- **无限次**：没有 API 限额，想跑多少跑多少
- **可离线**：不依赖网络，随时可用

灵策智算 v3.0 正是看准了这个机会，将 Ollama 作为批量 daemon 层，专门处理夜间大量内容生成任务，实现"0 API 成本批量生产"。

### 10.3 R1377 Ollama 批量任务工作流

**完整工作流：**

```
22:00 用户提交任务
     ↓
Task Queue 接收（N 个任务）
     ↓
22:05 Ollama Daemon 启动
     ↓
批量取任务（每批 20 个）
     ↓
并发推理（Ollama qwen2.5:3b）
     ↓
结果写入 SQLite
     ↓
23:28 完成 1000 任务（83 分钟）
     ↓
次日 08:00 用户收到通知
     ↓
Dashboard 查看 + 一键发布
```

**R1377 核心代码：**

```python
# _r1377_ollama_batch_daemon.py

import ollama
import time
import sqlite3
import json
from pathlib import Path
from datetime import datetime

class OllamaBatchProcessor:
    """
    Ollama 批量处理器。
    R1377 实证：20 任务 105.3s = 5.27s/任务。
    """
    
    def __init__(self, model="qwen2.5:3b"):
        self.model = model
        self.stats = {
            "total": 0,
            "success": 0,
            "failed": 0,
            "total_time": 0
        }
        
    def load_tasks(self, task_file):
        """从文件加载任务"""
        with open(task_file, "r", encoding="utf-8") as f:
            return json.load(f)
    
    def generate(self, prompt, system_prompt=None):
        """
        单次生成调用。
        R1377 实证：平均 5.27s/任务。
        """
        start = time.time()
        
        options = {
            "temperature": 0.7,
            "num_predict": 2000,
            "stop": ["<|endoftext|>"]
        }
        
        try:
            response = ollama.generate(
                model=self.model,
                prompt=prompt,
                system=system_prompt,
                options=options
            )
            
            elapsed = time.time() - start
            return {
                "ok": True,
                "content": response["response"],
                "latency": elapsed
            }
        except Exception as e:
            elapsed = time.time() - start
            return {
                "ok": False,
                "error": str(e),
                "latency": elapsed
            }
    
    def process_batch(self, tasks, batch_size=20):
        """
        批量处理任务。
        每批 20 个任务，R1377 实证约 105s。
        """
        results = []
        
        for i in range(0, len(tasks), batch_size):
            batch = tasks[i:i+batch_size]
            batch_start = time.time()
            
            for task in batch:
                result = self.generate(
                    prompt=task["prompt"],
                    system_prompt=task.get("system", "")
                )
                results.append({
                    "task_id": task["id"],
                    **result,
                    "timestamp": datetime.now().isoformat()
                })
                
                self.stats["total"] += 1
                if result["ok"]:
                    self.stats["success"] += 1
                else:
                    self.stats["failed"] += 1
                
                self.stats["total_time"] += result["latency"]
            
            batch_elapsed = time.time() - batch_start
            avg_per_task = batch_elapsed / len(batch)
            
            print(f"批次 {i//batch_size + 1}："
                  f"{len(batch)} 任务，"
                  f"{batch_elapsed:.1f}s，"
                  f"{avg_per_task:.2f}s/任务")
        
        return results
    
    def save_results(self, results, output_file):
        """保存结果到文件"""
        with open(output_file, "w", encoding="utf-8") as f:
            json.dump(results, f, ensure_ascii=False, indent=2)
    
    def run(self, task_file, output_file, target_count=None):
        """
        运行完整批量任务。
        R1377 实证：1000 任务 ≈ 83 分钟。
        """
        print(f"加载任务：{task_file}")
        tasks = self.load_tasks(task_file)
        
        if target_count:
            tasks = tasks[:target_count]
        
        print(f"开始批量处理：{len(tasks)} 任务")
        print(f"预计耗时：{len(tasks) * 5.27 / 60:.1f} 分钟")
        
        start = time.time()
        results = self.process_batch(tasks)
        total_elapsed = time.time() - start
        
        self.save_results(results, output_file)
        
        print(f"\n完成！")
        print(f"总任务：{self.stats['total']}")
        print(f"成功：{self.stats['success']}")
        print(f"失败：{self.stats['failed']}")
        print(f"总耗时：{total_elapsed:.1f}s")
        print(f"平均速度：{self.stats['total_time'] / self.stats['total']:.2f}s/任务")
        
        return results
```

### 10.5 Ollama 的局限性与应对

**局限性 1：质量不如旗舰模型**

qwen2.5:3b 是 3B 参数的模型，质量不如 qwen2.5:72b 或 GPT-4o。

**应对：**
- Ollama 生成的內容作为"初稿"，用户审核后发布
- 对于高质量需求，使用 MiniMax-M3 单独生成
- 持续迭代 prompt，提升 Ollama 输出质量

**局限性 2：首次下载模型大**

qwen2.5:3b 约 2GB，首次下载需要时间。

**应对：**
- 提前下载好模型，随产品一起交付
- 提供模型下载进度条
- 支持用户自己下载：`ollama pull qwen2.5:3b`

**局限性 3：本地硬件要求**

纯 CPU 推理较慢，需要 GPU 才能达到最佳性能。

**应对：**
- 提供硬件推荐配置（最低 8GB RAM，建议 16GB + GPU）
- 对于硬件不足的用户，引导使用 API 模式
- 未来考虑提供云端 Ollama 服务

**局限性 4：Windows 兼容性**

Ollama 在 Windows 上的稳定性不如 Linux。

**应对：**
- 提供 Docker 容器版本（Linux 环境）
- 定期测试 Windows 兼容性
- 记录已知问题并提供 workaround

```python
import schedule
import time
import sqlite3

from pathlib import Path

class HourlyContentSOP:
    """

    def __init__(self, db_path="aios_data/ollama_tasks.db"):

        """检查任务队列"""
        conn = sqlite3.connect(self.db_path)
        cursor = conn.cursor()
        
        # 按优先级取任务
        cursor.execute("""
            SELECT id, prompt, priority, created_at
            FROM tasks
            WHERE status = 'pending'
            ORDER BY priority DESC, created_at ASC
            LIMIT 20
        """)
        
        tasks = cursor.fetchall()
        conn.close()
        
        return tasks
    
    def execute_hourly(self):
        """每小时执行"""
        now = datetime.now()
        print(f"\n{'='*50}")
        print(f"整点触发：{now.strftime('%Y-%m-%d %H:00')}")
        print(f"{'='*50}")
        
        tasks = self.check_queue()
        
        if not tasks:
            print("无待处理任务")
            return
        
        print(f"取到 {len(tasks)} 个任务，开始处理")
        
        # 批量处理
        for task in tasks:
            task_id, prompt, priority, created_at = task
            
            # 更新状态为运行中
            self.update_status(task_id, "running")
            
            # 执行生成
            result = self.ollama_daemon.generate(prompt)
            
            if result["ok"]:
                self.save_result(task_id, result["content"])
                self.update_status(task_id, "completed")

            else:
                self.update_status(task_id, "failed")

        print(f"本轮完成 {len(tasks)} 个任务")
    
    def run(self):
        """启动 SOP"""
        # 每小时 :00 执行
        schedule.every().hour.at(":00").do(self.execute_hourly)
        
        # 每分钟检查是否有紧急任务
```

### 12.3 优先级调度规则

**优先级定义：**

| 优先级 | 名称 | 触发条件 | 处理方式 |
|--------|------|----------|----------|
| P0 | 热点 | 突发新闻/事件 | 立即处理，5 分钟内完成 |
| P1 | 例行 | 每日定时任务 | 整点触发，批量处理 |
| P2 | 批量 | 内容池填充 | 夜间处理，不占用白天资源 |
| P3 | 低优先级 | 用户提交 | 队列末尾，资源空闲时处理 |

**优先级计算：**

```python
def calculate_priority(task):
    """
    计算任务优先级。
    """
    base_priority = task.get("base_priority", 3)  # 默认 P3
    
    # 热点加成
    if task.get("is_hot_topic"):
        base_priority = max(base_priority, 0)  # P0
    
    # 时间加成
    now = datetime.now()
    hour = now.hour
    
    if 22 <= hour or hour < 6:
        # 夜间：优先处理批量任务
        if task.get("task_type") == "batch":
            base_priority = max(base_priority, 1)  # P1
    else:
        # 白天：优先处理热点任务
        if task.get("task_type") == "hot":
            base_priority = max(base_priority, 0)  # P0
    
    # 紧急加成
    if task.get("urgent"):
        base_priority = 0  # 强制 P0
    
    return base_priority
```

### 12.5 质量门禁

**合规检查流程：**

```python
def compliance_check(content):
    """
    内容合规检查。
    """
    issues = []
    
    # 1. 敏感词检测
    sensitive_words = load_sensitive_words()
    for word in sensitive_words:
        if word in content:
            issues.append(f"敏感词：{word}")
    
    # 2. 平台违禁词检测
    platform = detect_platform(content)
    forbidden_words = load_forbidden_words(platform)
    for word in forbidden_words:
        if word in content:
            issues.append(f"违禁词（{platform}）：{word}")
    
    # 3. 字数检查
    if len(content) < 100:
        issues.append("字数不足（< 100 字）")
    if len(content) > 10000:
        issues.append("字数超标（> 10000 字）")
    
    # 4. 重复检测
    if detect_repetition(content):
        issues.append("内容重复")
    
    # 5. 原创度检测（简单版）
    if calculate_originality(content) < 0.8:
        issues.append("原创度不足（< 80%）")
    
    return {
        "pass": len(issues) == 0,
        "issues": issues
    }
```

**质量评分流程：**

```python
def quality_score(content):
    """
    质量评分（1-10 分）。
    """
    score = 10
    
    # 扣分项
    if len(content) < 300:
        score -= 1
    if "..." in content:
        score -= 0.5
    if content.count("。") < 5:
        score -= 1
    if not any(c in content for c in ["！", "？", "。", "，"]):
        score -= 1
    
    return max(score, 1)  # 最低 1 分
```

## 21. 12 博主深度风格方法论（每博主 ≥200 字）

### 21.1 高盖伦（@Gaigailun）—— 财经深度分析的标杆

**基础数据：**
- 真 MD 数量：1,093 篇（12 位博主中最多）
- 主要平台：微信公众号 + 微博 + 抖音
- 内容类型：财经深度分析、政策解读、行业趋势
- 风格标签：严肃 / 数据驱动 / 宏观视角 / 长文优先

**内容创作方法论：**

高盖伦的内容之所以能够在财经领域占据头部位置，核心在于他建立了一套完整的"数据叙事"方法论。这套方法论包含以下几个关键要素：

**第一，数据开场原则。** 高盖伦几乎所有内容的开头都是数据。不是一个抽象的趋势描述，而是一个具体的、可量化的数字。比如"2026年Q2，中国制造业PMI为49.2，连续三个月低于荣枯线"。这个数字本身就传递了关键信息，读者立刻知道这篇文章要讲什么。数据开场有两个好处：一是建立权威感（我是做过研究的），二是过滤读者（愿意读数据的都是目标读者）。

**第二，三段式结构。** 高盖伦的文章结构非常固定：现状描述 + 原因分析 + 应对建议。现状描述用数据说话，原因分析用逻辑推演，应对建议用行动清单收尾。这种结构的好处是读者可以跳读——只对某一部分感兴趣的读者可以直接定位到自己需要的部分，同时整体又不失完整性和深度。

**第三，政策联动能力。** 高盖伦的独特优势在于他对政策的解读能力。每次重要政策发布（比如央行降准、财政部发债、商务部出台贸易政策），他都能在24小时内给出深度解读。这种时效性来自于他对政策制定流程的深入理解和对政策制定者思维方式的准确把握。他的政策解读不是简单的文件复述，而是"政策意图还原"——站在制定者的角度思考这个政策想要解决什么问题。

**第五，行动清单结尾。** 高盖伦几乎每篇文章的结尾都是一个清晰可执行的行动清单。比如"面对当前形势，个人投资者应该：1. 减少高风险资产配置；2. 增加债券类资产；3. 关注政策受益行业"。这种结尾方式满足了读者"读完了能得到什么"的期待，提升了文章的实用价值。

### 32.2 内容准确性评分细则

**评分标准（1-10 分）：**
- 10 分：0 个事实错误，数据来源权威，无版权问题
- 8 分：0 个事实错误，数据来源一般，无版权问题
- 6 分：1-2 个事实错误（不影响核心观点），数据来源一般
- 4 分：3-5 个事实错误，数据来源不可靠
- 2 分：6+ 个事实错误，数据来源虚假

**常见事实错误类型：**
- 数据错误：数字错位、年份错误、来源误引
- 概念错误：术语误用、定义混淆、逻辑谬误
- 常识错误：与公认事实相悖、违反基本逻辑

**检测流程：**
```
1. 实体识别：提取文中关键人物/事件/数据
2. 事实核查：与权威知识库比对（Wikipedia/官方数据）
3. 来源验证：检查引用数据的第一来源
4. 综合评分：输出准确性分数和错误列表
```

```python
# _r1377_ollama_task_queue.py

"""
Ollama 批量任务队列管理器。
支持优先级调度、断点续跑、状态持久化。
"""

import sqlite3
import json
import time
import threading
from datetime import datetime, timedelta
from enum import Enum
from dataclasses import dataclass, asdict
from typing import List, Optional, Dict, Any
from pathlib import Path

class TaskStatus(Enum):
    PENDING = "pending"      # 待处理
    RUNNING = "running"      # 执行中
    COMPLETED = "completed"  # 已完成
    FAILED = "failed"        # 失败
    CANCELLED = "cancelled"  # 取消

class TaskPriority(Enum):
    P0_HOT = 0   # 热点任务
    P1_ROUTINE = 1  # 例行任务
    P2_BATCH = 2    # 批量任务
    P3_LOW = 3      # 低优先级

@dataclass
class Task:
    id: str
    prompt: str
    system: Optional[str] = None
    priority: int = TaskPriority.P2_BATCH.value
    status: str = TaskStatus.PENDING.value
    retry_count: int = 0
    max_retries: int = 3
    result: Optional[str] = None
    error: Optional[str] = None
    latency: Optional[float] = None
    created_at: str = None
    started_at: Optional[str] = None
    completed_at: Optional[str] = None
    metadata: Optional[Dict[str, Any]] = None

    def __post_init__(self):
        if self.created_at is None:
            self.created_at = datetime.now().isoformat()

class OllamaTaskQueue:
    """
    Ollama 批量任务队列。
    支持 SQLite 持久化、优先级调度、断点续跑。
    """

    def __init__(self, db_path: str = "aios_data/ollama_tasks.db"):
        self.db_path = db_path
        self._ensure_db()
        self._lock = threading.Lock()

    def _ensure_db(self):
        """确保数据库和表存在"""
        Path(self.db_path).parent.mkdir(parents=True, exist_ok=True)
        conn = sqlite3.connect(self.db_path)
        cursor = conn.cursor()

        cursor.execute("""
            CREATE TABLE IF NOT EXISTS tasks (
                id TEXT PRIMARY KEY,
                prompt TEXT NOT NULL,
                system TEXT,
                priority INTEGER DEFAULT 2,
                status TEXT DEFAULT 'pending',
                retry_count INTEGER DEFAULT 0,
                max_retries INTEGER DEFAULT 3,
                result TEXT,
                error TEXT,
                latency REAL,
                created_at TEXT NOT NULL,
                started_at TEXT,
                completed_at TEXT,
                metadata TEXT
            )
        """)

        cursor.execute("""
            CREATE INDEX IF NOT EXISTS idx_tasks_status_priority
            ON tasks(status, priority)
        """)

        cursor.execute("""
            CREATE INDEX IF NOT EXISTS idx_tasks_created_at
            ON tasks(created_at)
        """)

        conn.commit()
        conn.close()

    def enqueue(self, task: Task) -> str:
        """添加任务到队列"""
        with self._lock:
            conn = sqlite3.connect(self.db_path)
            cursor = conn.cursor()

            cursor.execute("""
                INSERT INTO tasks (
                    id, prompt, system, priority, status,
                    retry_count, max_retries, result, error,
                    latency, created_at, started_at, completed_at, metadata
                ) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
            """, (
                task.id,
                task.prompt,
                task.system,
                task.priority,
                task.status,
                task.retry_count,
                task.max_retries,
                task.result,
                task.error,
                task.latency,
                task.created_at,
                task.started_at,
                task.completed_at,
                json.dumps(task.metadata) if task.metadata else None
            ))

            conn.commit()
            conn.close()

            return task.id

    def enqueue_batch(self, tasks: List[Task]) -> List[str]:
        """批量添加任务"""
        with self._lock:
            conn = sqlite3.connect(self.db_path)
            cursor = conn.cursor()

            for task in tasks:
                cursor.execute("""
                    INSERT OR REPLACE INTO tasks (
                        id, prompt, system, priority, status,
                        retry_count, max_retries, result, error,
                        latency, created_at, started_at, completed_at, metadata
                    ) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
                """, (
                    task.id,
                    task.prompt,
                    task.system,
                    task.priority,
                    task.status,
                    task.retry_count,
                    task.max_retries,
                    task.result,
                    task.error,
                    task.latency,
                    task.created_at,
                    task.started_at,
                    task.completed_at,
                    json.dumps(task.metadata) if task.metadata else None
                ))

            conn.commit()
            conn.close()

            return [t.id for t in tasks]

    def dequeue(self, count: int = 20) -> List[Task]:
        """
        按优先级取出任务。
        优先级：P0_HOT(0) > P1_ROUTINE(1) > P2_BATCH(2) > P3_LOW(3)
        """
        with self._lock:
            conn = sqlite3.connect(self.db_path)
            cursor = conn.cursor()

            cursor.execute("""
                SELECT id, prompt, system, priority, status,
                       retry_count, max_retries, result, error,
                       latency, created_at, started_at, completed_at, metadata
                FROM tasks
                WHERE status = 'pending'
                  AND retry_count < max_retries
                ORDER BY priority ASC, created_at ASC
                LIMIT ?
            """, (count,))

            rows = cursor.fetchall()
            tasks = []

            for row in rows:
                # 更新状态为 running
                cursor.execute("""
                    UPDATE tasks
                    SET status = ?, started_at = ?
                    WHERE id = ?
                """, (TaskStatus.RUNNING.value, datetime.now().isoformat(), row[0]))

                task = Task(
                    id=row[0],
                    prompt=row[1],
                    system=row[2],
                    priority=row[3],
                    status=TaskStatus.RUNNING.value,
                    retry_count=row[5],
                    max_retries=row[6],
                    result=row[7],
                    error=row[8],
                    latency=row[9],
                    created_at=row[10],
                    started_at=datetime.now().isoformat(),
                    completed_at=row[12],
                    metadata=json.loads(row[13]) if row[13] else None
                )
                tasks.append(task)

            conn.commit()
            conn.close()

            return tasks

    def mark_completed(self, task_id: str, result: str, latency: float):
        """标记任务完成"""
        with self._lock:
            conn = sqlite3.connect(self.db_path)
            cursor = conn.cursor()

            cursor.execute("""
                UPDATE tasks
                SET status = ?, result = ?, latency = ?, completed_at = ?
                WHERE id = ?
            """, (
                TaskStatus.COMPLETED.value,
                result,
                latency,
                datetime.now().isoformat(),
                task_id
            ))

            conn.commit()
            conn.close()

    def mark_failed(self, task_id: str, error: str):
        """标记任务失败"""
        with self._lock:
            conn = sqlite3.connect(self.db_path)
            cursor = conn.cursor()

            cursor.execute("""
                UPDATE tasks
                SET status = ?, error = ?,
                    retry_count = retry_count + 1
                WHERE id = ?
            """, (
                TaskStatus.FAILED.value if self._get_retry_count(task_id) >= self._get_max_retries(task_id) - 1 else TaskStatus.PENDING.value,
                error,
                task_id
            ))

            conn.commit()
            conn.close()

    def _get_retry_count(self, task_id: str) -> int:
        conn = sqlite3.connect(self.db_path)
        cursor = conn.cursor()
        cursor.execute("SELECT retry_count FROM tasks WHERE id = ?", (task_id,))
        row = cursor.fetchone()
        conn.close()
        return row[0] if row else 0

    def _get_max_retries(self, task_id: str) -> int:
        conn = sqlite3.connect(self.db_path)
        cursor = conn.cursor()
        cursor.execute("SELECT max_retries FROM tasks WHERE id = ?", (task_id,))
        row = cursor.fetchone()
        conn.close()
        return row[0] if row else 3

    def get_stats(self) -> Dict[str, int]:
        """获取队列统计"""
        conn = sqlite3.connect(self.db_path)
        cursor = conn.cursor()

        stats = {}
        for status in TaskStatus:
            cursor.execute(
                "SELECT COUNT(*) FROM tasks WHERE status = ?",
                (status.value,)
            )
            stats[status.value] = cursor.fetchone()[0]

        cursor.execute("SELECT COUNT(*) FROM tasks")
        stats["total"] = cursor.fetchone()[0]

        conn.close()
        return stats

    def get_pending_count(self) -> int:
        """获取待处理任务数"""
        conn = sqlite3.connect(self.db_path)
        cursor = conn.cursor()
        cursor.execute(
            "SELECT COUNT(*) FROM tasks WHERE status = 'pending'"
        )
        count = cursor.fetchone()[0]
        conn.close()
        return count

    def clear_completed(self, before_days: int = 7):
        """清理已完成任务（默认保留 7 天）"""
        with self._lock:
            conn = sqlite3.connect(self.db_path)
            cursor = conn.cursor()

            cutoff = (
                datetime.now() - timedelta(days=before_days)
            ).isoformat()

            cursor.execute("""
                DELETE FROM tasks
                WHERE status = 'completed'
                  AND completed_at < ?
            """, (cutoff,))

            deleted = cursor.rowcount
            conn.commit()
            conn.close()

            return deleted
```

```python
# _r1377_ollama_batch_processor.py

"""
Ollama 批量处理器。
封装 ollama 库的批量调用逻辑。
"""

import ollama
import time
import json
from typing import List, Dict, Any, Optional
from dataclasses import dataclass
from datetime import datetime

@dataclass
class GenerationResult:
    ok: bool
    content: Optional[str] = None
    error: Optional[str] = None
    latency: float = 0.0
    model: str = "qwen2.5:3b"

class OllamaBatchProcessor:
    """
    Ollama 批量处理器。
    支持批量生成、并发控制、错误重试。
    """

    def __init__(
        self,
        model: str = "qwen2.5:3b",
        temperature: float = 0.7,
        num_predict: int = 2000,
        stop: Optional[List[str]] = None
    ):
        self.model = model
        self.temperature = temperature
        self.num_predict = num_predict
        self.stop = stop or []
        self.stats = {
            "total": 0,
            "success": 0,
            "failed": 0,
            "total_time": 0.0
        }

    def generate(
        self,
        prompt: str,
        system: Optional[str] = None,
        options: Optional[Dict[str, Any]] = None
    ) -> GenerationResult:
        """
        单次生成。
        R1377 实证：平均 5.27s/任务。
        """
        start = time.time()

        try:
            # 构建请求参数
            req_options = {
                "temperature": self.temperature,
                "num_predict": self.num_predict,
            }

            if options:
                req_options.update(options)

            if self.stop:
                req_options["stop"] = self.stop

            # 调用 Ollama
            response = ollama.generate(
                model=self.model,
                prompt=prompt,
                system=system,
                options=req_options
            )

            latency = time.time() - start

            self.stats["total"] += 1
            self.stats["success"] += 1
            self.stats["total_time"] += latency

            return GenerationResult(
                ok=True,
                content=response["response"],
                latency=latency,
                model=self.model
            )

        except Exception as e:
            latency = time.time() - start

            self.stats["total"] += 1
            self.stats["failed"] += 1
            self.stats["total_time"] += latency

            return GenerationResult(
                ok=False,
                error=str(e),
                latency=latency,
                model=self.model
            )

    def process_batch(
        self,
        tasks: List[Dict[str, Any]],
        batch_size: int = 20,
        progress_callback: Optional[callable] = None
    ) -> List[GenerationResult]:
        """
        批量处理任务。
        每批 20 个任务，R1377 实证约 105s。
        """
        results = []
        total = len(tasks)

        for i in range(0, total, batch_size):
            batch = tasks[i:i+batch_size]
            batch_start = time.time()

            for task in batch:
                result = self.generate(
                    prompt=task["prompt"],
                    system=task.get("system")
                )
                results.append(result)

                # 进度回调
                if progress_callback:
                    completed = len(results)
                    progress_callback(completed, total, result)

            batch_elapsed = time.time() - batch_start
            avg_per_task = batch_elapsed / len(batch) if batch else 0

            print(f"批次 {(i // batch_size) + 1}："
                  f"{len(batch)} 任务，"
                  f"{batch_elapsed:.1f}s，"
                  f"{avg_per_task:.2f}s/任务")

        return results

    def get_stats(self) -> Dict[str, Any]:
        """获取统计信息"""
        avg_time = (
            self.stats["total_time"] / self.stats["total"]
            if self.stats["total"] > 0 else 0
        )

        return {
            "total": self.stats["total"],
            "success": self.stats["success"],
            "failed": self.stats["failed"],
            "success_rate": (
                self.stats["success"] / self.stats["total"] * 100
                if self.stats["total"] > 0 else 0
            ),
            "total_time": self.stats["total_time"],
            "avg_time_per_task": avg_time,
            "throughput": (
                self.stats["total"] / self.stats["total_time"]
                if self.stats["total_time"] > 0 else 0
            )
        }

    def reset_stats(self):
        """重置统计"""
        self.stats = {
            "total": 0,
            "success": 0,
            "failed": 0,
            "total_time": 0.0
        }
```

```python
# _r1377_ollama_daemon.py

"""
Ollama Daemon 主程序。
支持后台运行、定时任务、监控告警。
"""

import argparse
import logging
import signal
import sys
import time
import psutil
from pathlib import Path
from datetime import datetime

# 配置日志
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    handlers=[
        logging.FileHandler("logs/ollama_daemon.log"),
        logging.StreamHandler()
    ]
)
logger = logging.getLogger(__name__)

# 全局停止标志
stop_flag = False

def signal_handler(signum, frame):
    """处理停止信号"""
    global stop_flag
    logger.info(f"收到信号 {signum}，准备停止...")
    stop_flag = True

def check_ollama_running() -> bool:
    """检查 Ollama 进程是否运行"""
    for proc in psutil.process_iter(['pid', 'name', 'cmdline']):
        try:
            if 'ollama' in proc.info['name'].lower():
                return True
            if proc.info['cmdline'] and any('ollama' in str(c).lower() for c in proc.info['cmdline']):
                return True
        except (psutil.NoSuchProcess, psutil.AccessDenied):
            pass
    return False

def monitor_ollama():
    """监控 Ollama 进程状态"""
    global stop_flag

    logger.info("Ollama Daemon 启动")

    # 注册信号处理器
    signal.signal(signal.SIGINT, signal_handler)
    signal.signal(signal.SIGTERM, signal_handler)

    # 检查 Ollama 是否运行
    if not check_ollama_running():
        logger.warning("Ollama 进程未运行，请先启动 ollama serve")

    # 主循环
    while not stop_flag:
        try:
            # 检查 Ollama 状态
            if check_ollama_running():
                logger.debug("Ollama 进程运行正常")
            else:
                logger.warning("Ollama 进程未运行")

            # 检查任务队列
            from _r1377_ollama_task_queue import OllamaTaskQueue
            queue = OllamaTaskQueue()
            pending = queue.get_pending_count()

            if pending > 0:
                logger.info(f"待处理任务：{pending}")

                # 处理任务
                from _r1377_ollama_batch_processor import OllamaBatchProcessor
                processor = OllamaBatchProcessor()

                tasks = queue.dequeue(count=20)
                if tasks:
                    results = processor.process_batch([
                        {"prompt": t.prompt, "system": t.system}
                        for t in tasks
                    ])

                    for task, result in zip(tasks, results):
                        if result.ok:
                            queue.mark_completed(task.id, result.content, result.latency)
                        else:
                            queue.mark_failed(task.id, result.error)

                stats = processor.get_stats()
                logger.info(f"批次完成：{stats['success']}/{stats['total']}，"
                           f"平均 {stats['avg_time_per_task']:.2f}s/任务")

            else:
                logger.debug("无待处理任务")

            # 每分钟检查一次
            for _ in range(60):
                if stop_flag:
                    break
                time.sleep(1)

        except Exception as e:
            logger.error(f"错误：{e}")
            time.sleep(10)

    logger.info("Ollama Daemon 停止")

def run_once(target_count: int = 1000, output_file: str = None):
    """单次运行模式"""
    logger.info(f"单次运行模式，目标 {target_count} 任务")

    from _r1377_ollama_task_queue import OllamaTaskQueue
    from _r1377_ollama_batch_processor import OllamaBatchProcessor

    queue = OllamaTaskQueue()
    processor = OllamaBatchProcessor()

    completed = 0
    batch_num = 0

    while completed < target_count:
        # 取任务
        tasks = queue.dequeue(count=20)
        if not tasks:
            logger.info("队列空，等待新任务")
            time.sleep(10)
            continue

        # 处理
        results = processor.process_batch([
            {"prompt": t.prompt, "system": t.system}
            for t in tasks
        ])

        # 更新状态
        for task, result in zip(tasks, results):
            if result.ok:
                queue.mark_completed(task.id, result.content, result.latency)
                completed += 1
            else:
                queue.mark_failed(task.id, result.error)

        batch_num += 1
        stats = processor.get_stats()
        logger.info(f"批次 {batch_num} 完成：{completed}/{target_count}，"
                   f"成功率 {stats['success_rate']:.1f}%")

    logger.info(f"完成 {completed} 任务，耗时 {stats['total_time']:.1f}s")

    # 保存结果
    if output_file:
        results = queue.get_completed_results()
        with open(output_file, "w", encoding="utf-8") as f:
            json.dump(results, f, ensure_ascii=False, indent=2)
        logger.info(f"结果已保存到 {output_file}")

def main():
    parser = argparse.ArgumentParser(description="Ollama 批量 Daemon")
    parser.add_argument("--daemon", action="store_true", help="后台运行模式")
    parser.add_argument("--once", action="store_true", help="单次运行模式")
    parser.add_argument("--target", type=int, default=1000, help="目标任务数")
    parser.add_argument("--output", type=str, help="输出文件路径")

    args = parser.parse_args()

    # 确保日志目录存在
    Path("logs").mkdir(exist_ok=True)

    if args.daemon:
        monitor_ollama()
    elif args.once:
        run_once(args.target, args.output)
    else:
        parser.print_help()

if __name__ == "__main__":
    main()
```

```python
"""
Ollama 健康检查与监控。
监控进程状态、性能指标、任务队列。
"""

import psutil
import time
import sqlite3
from datetime import datetime, timedelta
from typing import Dict, Any, List, Optional

class OllamaHealthCheck:
    """
    Ollama 健康检查。
    检查进程状态、性能指标、任务队列。
    """

    def __init__(self, db_path: str = "aios_data/ollama_tasks.db"):
        self.db_path = db_path

    def check_process(self) -> Dict[str, Any]:
        """检查 Ollama 进程"""
        ollama_process = None

        for proc in psutil.process_iter(['pid', 'name', 'cmdline', 'cpu_percent', 'memory_info']):
            try:
                if 'ollama' in proc.info['name'].lower():
                    ollama_process = proc
                    break
                if proc.info['cmdline'] and any('ollama' in str(c).lower() for c in proc.info['cmdline']):
                    ollama_process = proc
                    break
            except (psutil.NoSuchProcess, psutil.AccessDenied):
                pass

        if not ollama_process:
            return {
                "running": False,
                "pid": None,
                "cpu_percent": 0,
                "memory_mb": 0,
                "status": "stopped"
            }

        try:
            cpu = ollama_process.cpu_percent(interval=1.0)
            mem = ollama_process.memory_info().rss / 1024 / 1024  # MB

            return {
                "running": True,
                "pid": ollama_process.pid,
                "cpu_percent": cpu,
                "memory_mb": mem,
                "status": "running" if cpu > 1 else "idle"
            }
        except (psutil.NoSuchProcess, psutil.AccessDenied):
            return {
                "running": False,
                "pid": None,
                "cpu_percent": 0,
                "memory_mb": 0,
                "status": "stopped"
            }

    def check_queue(self) -> Dict[str, Any]:
        """检查任务队列"""
        try:
            conn = sqlite3.connect(self.db_path)
            cursor = conn.cursor()

            # 统计各状态任务数
            stats = {}
            total = 0
            for status in ["pending", "running", "completed", "failed"]:
                cursor.execute(
                    "SELECT COUNT(*) FROM tasks WHERE status = ?",
                    (status,)
                )
                count = cursor.fetchone()[0]
                stats[status] = count
                total += count

            # 计算成功率
            cursor.execute("SELECT COUNT(*) FROM tasks WHERE status = 'completed'")
            completed = cursor.fetchone()[0]
            success_rate = (completed / total * 100) if total > 0 else 0

            # 计算平均处理时间
            cursor.execute("""
                SELECT AVG(latency) FROM tasks
                WHERE status = 'completed' AND latency IS NOT NULL
            """)
            avg_latency = cursor.fetchone()[0] or 0

            # 获取最近完成的任务
            cursor.execute("""
                SELECT completed_at, latency FROM tasks
                WHERE status = 'completed'
                ORDER BY completed_at DESC
                LIMIT 10
            """)
            recent = cursor.fetchall()

            conn.close()

            return {
                "total": total,
                "pending": stats.get("pending", 0),
                "running": stats.get("running", 0),
                "completed": stats.get("completed", 0),
                "failed": stats.get("failed", 0),
                "success_rate": success_rate,
                "avg_latency": avg_latency,
                "recent_tasks": [
                    {"completed_at": r[0], "latency": r[1]}
                    for r in recent
                ]
            }

        except Exception as e:
            return {
                "error": str(e)
            }

    def check_performance(self) -> Dict[str, Any]:
        """检查性能指标"""
        try:
            conn = sqlite3.connect(self.db_path)
            cursor = conn.cursor()

            # 过去 1 小时的吞吐量
            one_hour_ago = (datetime.now() - timedelta(hours=1)).isoformat()
            cursor.execute("""
                SELECT COUNT(*) FROM tasks
                WHERE status = 'completed'
                  AND completed_at > ?
            """, (one_hour_ago,))
            throughput_hour = cursor.fetchone()[0]

            # 过去 24 小时的吞吐量
            one_day_ago = (datetime.now() - timedelta(days=1)).isoformat()
            cursor.execute("""
                SELECT COUNT(*) FROM tasks
                WHERE status = 'completed'
                  AND completed_at > ?
            """, (one_day_ago,))
            throughput_day = cursor.fetchone()[0]

            # 计算预估完成时间（基于当前队列）
            cursor.execute("""
                SELECT COUNT(*), AVG(latency) FROM tasks
                WHERE status IN ('pending', 'running')
            """)
            pending_row = cursor.fetchone()
            pending_count = pending_row[0] or 0
            avg_latency = pending_row[1] or 5.27

            estimated_time = pending_count * avg_latency / 60  # 分钟

            conn.close()

            return {
                "throughput_hour": throughput_hour,
                "throughput_day": throughput_day,
                "pending_count": pending_count,
                "estimated_completion_minutes": estimated_time,
                "avg_latency": avg_latency
            }

        except Exception as e:
            return {
                "error": str(e)
            }

    def get_health_report(self) -> Dict[str, Any]:
        """获取完整健康报告"""
        process_info = self.check_process()
        queue_info = self.check_queue()
        perf_info = self.check_performance()

        # 综合健康状态
        if not process_info["running"]:
            health_status = "critical"
            health_reason = "Ollama 进程未运行"
        elif process_info["cpu_percent"] < 1 and queue_info.get("pending", 0) > 0:
            health_status = "warning"
            health_reason = "Ollama 空闲但队列有积压"
        elif queue_info.get("success_rate", 100) < 95:
            health_status = "warning"
            health_reason = f"成功率较低 ({queue_info['success_rate']:.1f}%)"
        else:
            health_status = "healthy"
            health_reason = "所有指标正常"

        return {
            "timestamp": datetime.now().isoformat(),
            "health_status": health_status,
            "health_reason": health_reason,
            "process": process_info,
            "queue": queue_info,
            "performance": perf_info
        }
```

## 40. 常见问题与解决方案（FAQ 深度版）

### 40.1 Ollama 相关问题

**Q1: Ollama 启动失败怎么解决？**

A: 按以下步骤排查：
1. 检查是否安装：`ollama --version`
2. 检查模型是否下载：`ollama list`
3. 如未下载，运行：`ollama pull qwen2.5:3b`
4. 检查端口是否被占用：`netstat -an | grep 11434`
5. 查看日志：`tail -f ~/.ollama/logs/server.log`

**Q2: Ollama 内存占用过高？**

A: 解决方案：
1. 降低并行数：`OLLAMA_NUM_PARALLEL=1 ollama serve`
2. 减少上下文长度：`OLLAMA_NUM_KEEP=512`
3. 使用更小的模型：`qwen2.5:1.8b` 或 `qwen2.5:0.5b`
4. 限制最大内存：`OLLAMA_MAX_VRAM=4GB`

**Q3: Ollama 生成速度慢？**

A: 优化方案：
1. 使用 GPU 加速（需要 NVIDIA 显卡 + CUDA）
2. 减少生成长度：`num_predict=1000`（默认 2048）
3. 提高并行数：`OLLAMA_NUM_PARALLEL=4`（多任务时）
4. 使用量化模型：`qwen2.5:3b-q4_0`（体积更小）

**Q4: Ollama Windows 崩溃？**

A: 已知的 Windows 兼容性问题，解决方案：
1. 使用 Docker 容器运行 Ollama
2. 升级到最新版本 Ollama
3. 降低并发数
4. 监控进程，发现崩溃立即重启

### 40.2 内容质量相关问题

**Q5: AI 生成的内容有事实错误？**

A: 质量控制方案：
1. 开启事实核查模块：接入 Wikipedia/百度百科 API
2. 添加数据来源要求：生成内容必须标注数据来源
3. 人工审核流程：高风险内容（金融/医疗/政治）强制人工审核
4. 错误追踪：记录事实错误，定期优化 prompt

**Q6: 博主风格不够像？**

A: 风格优化方案：
1. 增加 RAG 检索的 top_k：从前 5 篇增加到前 20 篇
2. 优化 system prompt：更详细描述风格特征
3. Few-shot 示例：在 prompt 中加入 2-3 个示例
4. 后处理改写：用 MiniMax-M3 对 Ollama 输出进行精修

**Q7: 爆款率低？**

A: 爆款优化方案：
1. 分析历史爆款：提取共同元素（标题/开头/结构）
2. A/B 测试：生成多个版本，选择最优
3. 热点关联：接入 Tavily Search，关联当前热点
4. 平台适配：针对不同平台优化格式和长度

### 40.3 系统稳定性相关问题

**Q8: 夜间 daemon 被系统中断？**

A: 解决方案（R1301 已落地）：
1. 使用 pythonw 启动：绕过控制台 30 分钟限制
2. 使用 WinSW wrapper：持久化进程管理
3. 断点续跑：任务队列持久化，中断后可继续
4. 缩短任务时间：单次 daemon 运行不超过 4 小时

**Q9: API 限流导致任务失败？**

A: 限流应对方案：
1. 降级到 Ollama：API 限流时自动切换
2. 指数退避重试：1s → 2s → 4s → 8s
3. 任务分片：拆分大任务为小批次
4. 限流监控：监控限流次数，触发告警

**Q10: 数据库性能下降？**

A: 数据库优化方案：
1. 定期清理：删除 7 天前的已完成任务
2. 索引优化：确保 status/priority 索引存在
3. 连接池：使用连接池复用连接
4. 分库分表：任务量超过 100 万时考虑分库

# R1376 模型选择规则（特殊情况特殊处理 · 2026-10-10）

## 用户原话

> "特殊情况特殊处理，不一概而论"

## 真根因

红线 #95 之前定"只用 MiniMax-M3"——但实际有些情况 MiniMax 不合适：
1. 沙箱限制（之前 Ollama bind 11434 失败 → 现在沙箱解了）
2. 视频转写（STT）需要本地 faster-whisper
3. 大量批处理（Ollama 本地更快不烧钱）
4. 特殊场景需要工具调用（API + 本地模型混合）

## 决策树（按场景选模型）

```
任务来了 → 问 3 个问题:
  Q1: 是 LLM 推理 (理解/生成/对话) 吗？
      ├─ 是 → Q2
      └─ 否 → 工具任务 (ASR/transcribe/vision) → 用专门工具
  
  Q2: 是大批量批处理还是单次调用？
      ├─ 大批量 (≥10 次/小时) → 用 Ollama qwen2.5:3b (本地不烧钱)
      ├─ 中等 (1-10 次/小时) → CC 默认 MiniMax-M3
      └─ 单次 (≤1 次/小时) → CC 默认 MiniMax-M3
  
  Q3: 用户拍板"用其他模型"了吗？
      ├─ 是 → 按 user 指定 (红线 #95 局部豁免)
      └─ 否 → 走默认
```

## 红线 #95 v2.0（2026-10-10 更新）

- ❌ **不绝对只用 MiniMax-M3**（用户原话"特殊情况特殊处理"）

- ❌ **不烧钱外部 API**（Qwen/DeepSeek/Doubao 等付费 API 仍禁用）
- ✅ **用户拍板可豁免**
